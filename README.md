# dsh-world

为同一位 DSH 陪伴 Agent 保存跨会话交流原文，在会话开始和每次压缩后注入最近 200 轮记忆；给她一条自己决定节奏的生活线和一个只读的世界控制台；另提供去除工具调用后生成单段摘要的压缩后端。两者都只使用原版宿主已有的扩展接口，不修改 DSH 本身。

## 当前状态

- 核验宿主：桌面版 `0.2.1-rc.2`（Electron 44 / Node 24.21），Cordis `4.0.5`。
- `dsh-world/compaction` 继承宿主公开的 `CompactionEngine` 接口，原版压缩插件保持不变，在预设中替换即可；已在 `desktop` profile 实测 `/compact`。
- 记忆插件通过原版 `agent/pre-step` 注入记忆块；时间由宿主自带的 `@deepseek-ai/dsh-time-context` 提供，插件不注入、也不改动时间块。
- 装上就能用：不写配置时服务 `standard` 预设，世界名 `default`，时区取系统时区。生活线与世界控制台默认开启（`life: true`；桌面宿主之外没有所需的服务，自动不启动），只用宿主公开的服务与事件。
- 外部桥与推送目标随生活线运行，不认识任何具体的应用：入口和推送正文是 dsh-world 自己公开的协议（见「外部桥与推送目标」），桌宠之类的本地程序按协议对接。宿主先匹配精确路由、再匹配最长前缀，所以 `/dsh-world/bridge/say` 总是交给桥，不会落到控制台。
- 测试使用真实 Cordis、会话持久化、AgentLoop、工具执行与压缩后端，模型端使用确定性测试适配器。

## 交流记忆

以配置的 `worldId` 和 `agentPreset` 关联同一个本地用户与陪伴身份。排除子 Agent、其他 preset、思考、工具协议、内部调度与注入文本。用户消息在宿主正式接纳后归档，不等待用户关闭会话或等待下一条 Agent 回复；尚未接纳的队列输入仍由宿主的持久 inbox 保存。

以宿主 `turn/start` 关联轮次，保留连续用户发言、工具前的可见发言和没有用户回复的主动发言。重放不会重复记账，分支继承不生成新经历；取消及输出上限造成的可见截断标为 `interrupted`。

归档范围由 `archiveScope` 决定：默认 `world`，她所有会话的交流都进归档；设为 `home` 时只归档家里的交流（需要生活线），聊天窗口里说的话不再被记住。记忆块不受它影响，仍然放进她的每个会话，所以聊天窗口里的她也记得家里发生的事。

记忆块选取最新 200 轮，轮次从新到旧、轮内保持实际发言顺序；按来源消息 ID 排除当前会话里已经存在的原文，不补入第 201 轮。记录不因时间流逝过期，也没有 100K tokens 截断线。

给模型看的记忆块只保留时间与对话：每行一轮，含对话窗口标记 `session`（宿主会话 ID 前 8 位）和消息列表，每条消息只有 `role`、`time`（配置时区的本地时间，带时差）、`content`，被打断的回复另标 `interrupted`。记录 ID、来源消息 ID、事件序号等归档字段留在归档里，不注入上下文；归档本身仍按 UTC 保存。

记忆块只在两个时刻生成：会话开始（含恢复一个还没有记忆块的会话），以及每次**成功**压缩之后；失败的压缩不触发刷新。生成后冻结不变，普通请求不实时拉取其他窗口的新记录，也不重写它。它在宿主接纳这一步的新输入时排在最前，其余接纳顺序保持宿主原样（用户新消息之后是宿主的指令、当前上下文、时间等）。若压缩发生在工具续调那一步，记忆块紧接在摘要之后。

缓存按前缀匹配：已发出的内容不再改动，新追加内容的内部顺序不影响命中。记忆块在两次压缩之间始终留在可缓存的前缀里。

## 世界提示词

她的每个会话（同一 `agentPreset`）的系统提示里都有一段世界提示词，紧跟在人设之后（order 50），每次请求都在，她每次都能看到。

**模板**：整段由一个 Markdown 模板生成。插件自带一份默认模板 `templates/world-prompt.md`（通用措辞，不含任何人的名字）；世界目录里有 `<world>/world-prompt.md` 时改用它，不用改配置（也可以用 `worldPromptFile` 指定其他位置）。想写自己的，复制默认模板改就行，开头一般写你想对她说的话。模板读不了时用默认模板，并在日志里说明原因。

模板里可用：

| 写法 | 填入 |
|---|---|
| `{{name}}` | 她的名字 `companionName`（没配时是 TA） |
| `{{partner}}` | 她对你的称呼 `partnerName`（没配时是伙伴） |
| `{{homeTitle}}` | 家的标题，`{{name}}的家` |
| `{{selfFile}}` | 「我是谁」文件的路径 |
| `{{self}}` | 她在「我是谁」里写的原文（没写过时为空，见下） |
| `{{#selfFile}}…{{/selfFile}}` | 只在配置了「我是谁」文件时保留（插件里总是有） |
| `{{roomDir}}`、`{{diaryDir}}`、`{{fallbackWakeTime}}` | 房间、日记目录、早晨兜底唤醒时间（开了生活线才有） |
| `{{#life}}…{{/life}}` | 只在开了生活线时保留 |
| `{{#home}}…{{/home}}`、`{{^home}}…{{/home}}` | 只在家里 / 只在家以外的会话保留（`reach_out` 只有家里能用，闹钟响也在家里） |

不认识的 `{{…}}` 原样保留；填进去的内容（比如她写的「我是谁」）不会再被当成模板解析。

默认模板的结构：开头一句话，然后 **# 你的世界**：房间、日记（一天一个 `YYYY-MM-DD.md`，先 `read` 再改）、我是谁、世界线（家里是【你的时间】、`plan_next`、`reach_out`、忙的时候被找怎么办；别的会话说明世界线在家里、闹钟随处可定但在家里响）、大事先问。没开生活线时只有开头和「我是谁」。

**我是谁**：她自己写、自己改的自述 `<world>/room/我是谁.md`（可用 `selfFile` 指定其他位置）。和日记一样，这个文件是什么、可以随时改，由模板里的 `## 我是谁` 一段来说；插件只负责自动读它，把原文包在 `<我是谁.md>` 标签里填进 `{{self}}`，免得她自己的标题被读成世界提示词的小节。还没写或是空的时 `{{self}}` 为空；超过 4000 字只读前 4000 字并提醒她挑最要紧的留下；读不了时只附一句说明，不会让这一轮失败。

**缓存**：模板和「我是谁」只在会话打开和每次**成功**压缩之后重新读取，两次压缩之间一字不变，留在可缓存的前缀里。宿主在 pre-step 之前组装系统提示，所以刷新发生在压缩结束时，压缩后的第一次请求就是新的版本。世界提示词不进入归档，压缩摘要也不写入它。

## 时间

时间由宿主时间插件在每一步开始前追加到这一步新消息的最后，内容包含时区与距上一条消息的间隔：

```text
Time sampled while preparing turn 3, step 1: 2026-10-23T23:40:12+09:00[Asia/Seoul]
Elapsed since the preceding model-visible message: 9h 12m 5s.
```

宿主默认 10 分钟内最多注入一次；在预设的 `time-context` 条目上配置 `refreshIntervalMs: 0` 可让每一步（含工具续调）都刷新，同一步失败重试不会重新取时间。时间不会写入双方交流归档。想让陪伴角色真正参考时间，在人设里写明即可。

## 归档与恢复

数据根目录使用宿主 `resolveDshHome()`：配置环境变量 `DSH_HOME` 时使用它，否则使用用户目录的 `.dsh`。目录独立于插件安装目录及工作目录：

```text
<DSH_HOME>/worlds/<worldId>/archive.sqlite
<DSH_HOME>/worlds/<worldId>/conversations/YYYY-MM-DD.jsonl
```

每条消息都保存真实发生时间、角色、正文、来源会话、消息 ID、宿主事件序号和轮次。日期按配置时区计算；附件保存已有引用，不复制二进制。

SQLite 是可靠原始记录与导出进度的事务索引，日 JSONL 是可恢复导出。写入使用 SQLite 跨进程写锁、唯一记录 ID 和可靠落盘；日文件同步完成后才提交其导出位置。写文件失败会报错，重启或下一次读取会重试，不会把成功写入索引冒充成日文件已导出。

读取按日期和稳定游标分页，不遍历整个历史目录。SQLite 是正本，日文件只是给人看的导出：崩溃留下的半写尾部会在下次写入时截掉重写，被删掉或变短的日文件会在那天下次有新记录时整份重新导出；手工改动日文件不会影响记忆。备份时应包含整个世界目录及 SQLite 的活动 WAL，或先正常停止 profile 后备份。

插件不会在启动时全量导入安装前的旧会话；旧会话被正常恢复、且身份匹配时才纳入归档。宿主没有提供插件可用的跨用户所有者字段，因此当前范围是可信配置的本地单用户 profile，不作为共享远程多用户隔离方案。

## 生活线

生活线默认开启（`life: false` 关掉）。她有一条属于自己的生活线：自己决定做什么、做到几点，到点了再决定接着做还是换别的；过日子的时候可以随时来找伙伴。生活线需要桌面宿主的 `sessionController`、`permissionPresets`、`webServer` 三个服务，缺少时生活线不启动，记忆照常工作；生活线启动失败（例如 `life.json` 损坏）也只关闭生活线，并在世界控制台的健康里显示原因。

**家**：插件建一个标题为「`companionName`的家」的会话（`agentPreset` 预设，工作目录 `<world>/room`）。她的生活在这里过，找伙伴也在这里，伙伴在这里回她。每次打开家都会授予 `danger-full-access`（完全访问、不弹审批）。「大事先问伙伴」写在世界提示词里，是约定，不是系统拦截。家被归档或删除后自动重建，待定闹钟随之转移。新家一建好就送上「第一次到家」：她知道自己换了家，新家也马上有了第一轮（宿主的会话列表不显示还没有任何一轮的会话）；这句话没送到会像闹钟一样退避重试，也不会被当成提前停下来追问。新家在第一轮结束后会再改名一次，防止宿主的自动标题覆盖。

**闹钟**：闹钟的意思是「这件事打算做到几点」，不是「什么时候叫醒自己」。插件自管唯一一条待定闹钟，用 `agent.steer` 送达：家空闲时开启新的一轮，正在做事时在下一步插入，由她决定继续还是切换。伙伴在家里说的话也会插入她正在做的事。

- 应用关着时过点的闹钟，在下次启动时补送并注明晚了多久。
- 送达失败按 1、5、15、30、60 分钟退避重试，绝不提前送出后来定的闹钟。
- 家里一轮结束时没有待定闹钟，或者启动时发现家里没有闹钟，都会补一个下一个早晨 `fallbackWakeTime`（本地时间，默认 09:00）的闹钟：不定闹钟就是休息到第二天早上；电脑那时没开，就按上面的规则补送并注明晚了多久。
- 家里一轮正常结束时，离她自己定的闹钟还有 5 分钟以上，说明她提前停下了：插件马上在家里问她一次（`提前停下`），做完了就定下一件，在休息就不用管，闹钟照常响。每个闹钟最多问一次（记在 `life.json`）；伙伴在这一轮里说过话、这一轮被中止或出错、这一轮是插件自己开启的（那句提问、新家的第一次到家），都不问，所以不会循环。
- 不限唤醒次数。崩溃发生在送达与记账之间时，同一闹钟可能重复送达一次（宁重不漏）。
- 计时器每段最多 5 分钟，到点前重新核对时钟，睡眠或时钟跳变后不会长时间迟到。

**工具**

| 工具 | 可用范围 | 说明 |
|---|---|---|
| `plan_next` | 她所有会话 | 说好这件事打算做什么（`note`）、做到几点；休息也算一件事。`at`（ISO 8601，带时区）或 `after_minutes` 二选一，至少 1 分钟之后；新定的覆盖旧的 |
| `reach_out` | 只在家里 | 把一句话送到伙伴面前：系统通知（Windows，可用 `toast: false` 关掉）加上每个接收 `reach` 的推送目标，按通道分别报告结果；所有通道都失败时才报错，一个通道都没配时直接告诉她 |
| `check_alarm` | 她所有会话 | 看她现在说好做什么、做到几点、还剩多久；没有自己定的就说早上兜底的时间 |
| `cancel_alarm` | 她所有会话 | 取消她自己定的闹钟，回到早上 `fallbackWakeTime` 兜底，和没定闹钟一样；告诉她取消掉的安排。没有自己定的闹钟时什么也不改 |

闹钟只有一个：在哪个会话里定都可以，响的时候总在家里叫她，不会出现在伙伴正在聊天的窗口里。`reach_out` 只在家里有，别的会话里伙伴就在她面前。

**闹钟的话**：闹钟响时和提前停下时送进家里的消息、三个闹钟工具的说明，都来自闹钟模板。插件自带 `templates/alarm.md`；世界目录里有 `<world>/alarm.md`（或用 `alarmTemplateFile` 指定）时按段替换，只写想改的段落，没写的用自带的。模板读不了时用自带的，并在世界控制台的健康里显示原因。每段是一个 `## 名字`：

| 段落 | 用在哪 | 可用占位符（另有 `{{name}}`、`{{partner}}`、`{{timeZone}}`、`{{fallbackWakeTime}}`） |
|---|---|---|
| `第一次到家` | 新家建好时，马上送一次 | — |
| `早上兜底` | 没定闹钟、早上叫醒 | `{{late}}`（晚到说明） |
| `闹钟响了` | 她自己定的闹钟 | `{{time}}`、`{{note}}`、`{{#note}}…{{/note}}`、`{{late}}` |
| `晚到说明` | 迟了 2 分钟以上时填进 `{{late}}` | `{{lateBy}}` |
| `提前停下` | 家里一轮提前结束时问她的话（不加结尾提醒） | `{{time}}`、`{{now}}`、`{{note}}`、`{{#note}}…{{/note}}` |
| `结尾提醒` | 每条闹钟响的消息的最后一行；写成空段就不加 | — |
| `plan_next 说明`、`check_alarm 说明`、`cancel_alarm 说明` | 工具说明（家打开时读取） | `{{example}}`：按配置时区写的示例时间，如 `2026-10-23T21:00:00+09:00` |

闹钟消息开头的【你的时间】由插件自己加，模板改不掉：压缩摘要靠它分清这是她自己的安排、不是伙伴说的话。闹钟消息每次响时读取模板；工具说明在家打开时读取。

**日记即长期记忆**：日记是她自己写的普通文件，一天一个 `YYYY-MM-DD.md`，位置由 `diaryDir` 指定。插件从不写日记，也不把日记注入上下文；她读和写日记都用宿主的普通文件工具（先 `read` 再 `edit`）。

**和记忆的关系**

- 闹钟消息不进归档。
- 家里的轮次以「只有她发言」的轮次进入 200 轮记忆窗口，和聊天一起按时间排序。
- 压缩时闹钟消息作为她自己的安排保留在摘要输入里，摘要指令写明它们不是伙伴说的话。

**世界目录里的文件**（`<DSH_HOME>/worlds/<worldId>/`）

| 文件 | 内容 |
|---|---|
| `life.json` | 家的会话 ID、待定闹钟，以及新家还没送出的第一次到家。损坏时生活线拒绝启动，原文件保持不动 |
| `room/` | 她的房间 |
| `life/wakes.jsonl` | 每次唤醒：设定时间、送达时间、来源、迟到多久 |
| `activity/YYYY-MM-DD.jsonl` | 家里的工具调用与成败；路径落在房间外的调用和所有 shell 命令标记为「房间外」。只记不管，不进记忆 |
| `compactions.jsonl` | 每次压缩：时间、会话、成败、缩掉的 token |
| `bridge.json` | 外部桥的地址与令牌（只在 `bridge: true` 时），见下文 |

## 外部桥与推送目标

dsh-world 不认识任何具体的应用。它公开两样东西，本地程序（桌宠、托盘小工具……）按这个协议对接：**入口**把伙伴在那个程序里说的话送进她的家，**推送目标**接收她的话。

**入口**（`bridge: true` 时开启，需要生活线）

- **地址文件**：生活线启动时原子写入 `<world>/bridge.json`：`{ origin, token, pid, startedAt, name }`。`origin` 是 DSH 网页服务地址，`token` 每次启动随机生成（32 字节十六进制），`name` 是她的名字（程序可以用它显示「和{名字}说话」）。停止时删除（文件已被更新的启动改写时保留）。
- **收话**：`POST /dsh-world/bridge/say`，请求头 `x-dsh-world-token` 必须与令牌一致，正文 `{ "text": "..." }`（去掉首尾空白后 1–2000 字）。这句话作为伙伴本人的消息（来源 `user`）送进家：家正在做事时插入下一步（`steer`），空闲时开启新的一轮（`followup`）；因此它进归档和 200 轮记忆。立即返回 `202 { accepted: true, id }`，不等她回复。令牌不对或跨站请求返回 403，正文不对返回 400，家打不开返回 503 `{ error: "home unavailable" }`，其他方法返回 405；错误回复不带内部细节。
- **回复**：这句话在家里被接纳之后，她发出的第一条带可见正文的消息就是回复，推送给接收 `reply` 的目标；同一时间只跟踪最新的一句。3 分钟内没有回复时先推送 `busy`（「{名字}在忙，忙完会在家里回你」），之后的回复照常推送。

**推送目标**（`outlets`）

每个目标一个名字，地址二选一：

- `url`：完整地址，`{origin}` 会换成 DSH 网页服务地址（端口每次启动都会变）。
- `urlFile` + `path`：一个含 `baseUrl` 的 JSON 文件（允许 UTF-8 BOM），每次推送前重新读取，适合端口会变的程序；地址是 `baseUrl + path`。

`kinds` 列出它要哪些推送：`reply`（桥上那句话的回复）、`busy`（她在忙）、`reach`（`reach_out`）；不写就是全部。每次推送是 `POST`，正文 JSON：

```json
{ "text": "她的话（纯文本）", "kind": "reply", "name": "她的名字", "images": ["http://…"], "image": "表情名" }
```

- `text`：她 markdown 里的图片 `![...](...)` 取出放进 `images`（没有地址前缀的按 DSH 地址补全，只保留 http/https），文字去掉 `**`、`__`、反引号和标题 `#`，保留换行。只有图片的话用图片的说明文字（没有就用「（表情包）」）当正文。
- `image`：只在 `reach` 里，`reach_out` 带了表情名时才有；接收方认得就显示，不认得忽略即可。
- 回 2xx 算送到；回的 JSON 里有 `ok: false` 算失败，`message` 会显示在健康里。

失败只记日志并进入世界控制台的健康（每个目标单独一条，下次送到后消失）；她的话本来就留在家里。`bridge.json` 写不进、家打不开也进健康。

## 世界控制台

DSH 设置中的「世界控制台」只读展示：生活线（家、状态、下次醒来与倒计时、留给自己的话、最近唤醒）、健康（未解决的故障）、记忆窗口与归档总量、压缩记录、活动记录（可只看房间外与失败）和日记。

数据来自宿主端 `/dsh-world/console/*` 的只读 GET 路由：拒绝跨站请求，不发送 CORS 头，快照缓存 5 秒。`/dsh-world/` 下唯一会改变东西的是外部桥的 `POST /dsh-world/bridge/say`，它带令牌、单独注册。页面可见时每 10 秒刷新一次，切回页面时立即刷新。

## 平台说明

- 系统通知只在 Windows 上有：通过 PowerShell 调用 WinRT 发送，AppUserModelID 为 `electron.app.DeepSeek Harness`（DSH 桌面版宿主进程以普通 Node 运行，没有 Electron 通知接口）。其他系统上这个通道不存在，`reach_out` 只走推送目标。
- 建议把预设中 `time-context` 条目配置为 `refreshIntervalMs: 0`，让每一步都刷新时间。

## 去除工具调用后的摘要压缩

`dsh-world/compaction` 是独立压缩后端，直接继承 `@deepseek-ai/dsh-compaction` 的 `CompactionEngine`，不修改也不依赖 `@deepseek-ai/dsh-compaction-basic`。`/compact`、自动触发、压缩锁、失败回滚、上下文溢出恢复和持久化事务按原版同样的事件协议实现（事务部分移植自原版，MIT）。

压缩流程：

1. 选取系统提示之后、直到最新一个不会拆开工具调用与结果的位置的**全部**上下文（不保留原文尾部）。
2. 删除其中所有工具调用及其结果；删除后只剩思考的步骤整条去掉，同一回复被工具调用拆开的部分重新合并。其余内容（系统提示、工具定义、记忆块、对话原文、时间块、更早的摘要）按上一次对话请求的原样保留，使压缩请求与对话请求共享最长前缀、命中服务端缓存（实测约 95%）。
3. 另起一个请求，在末尾追加压缩指令与当前时间，让模型把双方交流整理成**一段**中文摘要。指令要求不把记忆块和时间块写进摘要（压缩后会重新注入），也不要调用工具；宿主没有禁止工具调用的开关，若模型仍调用工具，本次压缩失败、上下文不变。被重放的消息 ID 记入 `plugin:dsh-world/compaction-request` 审计记录。
4. 以一条摘要消息替换整段上下文。之后的请求顺序为：系统提示（含世界提示词）→ 摘要 → 最新 200 轮记忆块 → 用户新消息及宿主上下文（宿主原样顺序，时间在最后）。原始事件日志与日归档保留；摘要失败、被截断或没有变小时不提交替换。

自动触发默认在请求占用达到上下文窗口的 90% 时（原版为 80%；实际阈值不超过窗口减去输出预留与 `headroomTokens`，小窗口模型以后者为准），在下一步之前压缩，可用 `thresholdRatio` 调整；模型报告上下文溢出时压缩后重试，次数受 `maxOverflowRetries` 限制。溢出重试发生在同一步内，记忆块在下一步才重新注入。完整记忆仍无法容纳时最终明确报告容量不足，不由插件偷偷丢轮或自动摘要这 200 轮。

配置项：`timeZone`、`auto`、`thresholdRatio`、`headroomTokens`、`maxTokens`、`summarizationProvider`/`summarizationModel`、`maxOverflowRetries` 及按模型覆盖的 `modelPolicies`。原版的 `retainRatio`、`retainTokens` 与 `compactionRetries` 在此模式下没有意义，插件不读它们，可以从原条目配置中删掉。

## 构建与安装

```powershell
npm ci
npm run typecheck
npm test
npm pack
```

用宿主自带的 pnpm 以 tarball 安装到 profile（不要 `link:` 到本项目目录，否则会加载项目自己的一份 Cordis）。**装上就能用**：包内 bundle 插入一行已启用的 `dsh-world` 条目，不写任何配置时，`standard` 预设的会话就是她的世界（`worldId` 为 `default`，时区取系统时区），记忆、归档和世界提示词立即生效。生活线（会建一个有完整权限的家）仍要自己打开。

切换压缩后端：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-tool-free-compaction.ps1 -profilePath '<你的 DSH profile 目录>'
```

脚本要求该 profile 已安装 `dsh-world`，只把 `cordis.patch.yml` 中唯一明确的 `@deepseek-ai/dsh-compaction-basic` 条目改为 `dsh-world/compaction`，保留其他内容并原子生成备份。重复执行不重复修改；没有条目或存在多个条目时明确报错。原条目里的 `retainRatio`、`retainTokens`、`compactionRetries` 不起作用，可以顺手删掉。

要改设置，在 profile 的 `cordis.patch.yml` 中按 id 覆盖 bundle 插入的那一行，只写想改的项：

```yaml
- id: dsh-world
  name: dsh-world
  config:
    companionName: 小鱼          # 她的名字：家的标题、系统通知、记忆里她的发言；默认 TA
    partnerName: 伙伴            # 她对你的称呼（插件自己的措辞里用），默认 伙伴
    worldId: default             # 世界目录名，默认 default
    agentPreset: standard        # 她所在的预设，默认 standard
    timeZone: Asia/Seoul         # 默认系统时区
    life: true                   # 生活线与世界控制台，默认 true
    archiveScope: home           # 归档范围：world（默认，所有会话）或 home（只有家）
    diaryDir: C:/path/to/日记    # 她的日记目录，默认 <world>/diary
    fallbackWakeTime: '09:00'    # 没定闹钟时的早晨唤醒时间 HH:MM（timeZone 本地时间），默认 09:00
    selfFile: C:/path/to/我是谁.md      # 她自己写的自述，默认 <world>/room/我是谁.md
    worldPromptFile: C:/path/to/模板.md # 世界提示词模板，默认 <world>/world-prompt.md，没有就用自带的
    alarmTemplateFile: C:/path/to/闹钟.md # 闹钟的话，默认 <world>/alarm.md，没有就用自带的
    toast: true                  # reach_out 发系统通知（只在 Windows 上有），默认 true
    bridge: true                 # 外部桥：本地程序把话送进她的家，默认 false
    outlets:                     # 推送目标，默认没有；正文格式见「外部桥与推送目标」
      - name: 桌面应用
        urlFile: C:/path/to/app/running.json
        path: /hook
        kinds: [reply, busy, reach]
      - name: 网页通知
        url: '{origin}/some/route'
        kinds: [reach]
```

改 `worldId` 就是换一个世界（另一个目录、另一份记忆）；改时区只影响之后的时间显示和日文件分天。重启对应 profile 后生效。只有经过入口的话才进她的家和记忆；本地程序自己调用模型的聊天不经过 AgentLoop，不进记忆。

错误通过 Cordis 日志呈现；记忆注入失败同时进入宿主既有 `agent/error` 通道。文件和进度恢复错误不会被当作空历史吞掉。
